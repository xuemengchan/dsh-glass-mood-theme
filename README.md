# dsh-glass-mood-theme

给 DeepSeek Harness Web GUI 的 **Glassmorphism（玻璃拟态）主题**：材质跟着 Agent 的活动状态换情绪，每个状态可以配**自己的 MP4/WebM 动态壁纸**（状态切换时两段视频交叉淡入），三个面板的**不透明度 / 模糊 / 高光可分别设置**，并带一套苹果液态玻璃风格的静态边缘光。

| 状态 | 观感 | 触发条件 |
|---|---|---|
| **空闲** | **珍珠白玻璃**：白色为主调、中性冷灰描边、通透清爽；慢速溶解（900ms）、大范围柔焦（26px） | 没有任何会话在跑 |
| **工作** | **钢蓝玻璃**：冷调高对比、紧致模糊（13px）、冷色硬边内缘光、快切（260ms）+ 极慢呼吸光晕 | 有会话 `running`，或停在等待用户确认上 |

两种情绪是同一套玻璃材质换配方：色调、模糊半径、边框对比、过渡速度、光晕颜色。它**不替换**官方主题，而是叠在官方 `--dsw-*` 令牌之上 —— 设置里的「浅色 / 深色 / 跟随系统」仍然完全有效。

设置入口：**设置 → 通用**，两行：
- **玻璃主题 · 动态壁纸**（`order 13`）
- **玻璃主题 · 面板与光感**（`order 14`）

## 面板与光感（每个面板单独设置）

「左侧边栏 / 主界面 / 右侧边栏」各有一组 **不透明度 / 模糊 / 高光**：

| 控件 | 作用 |
|---|---|
| **不透明度** | 该面板底色的 **绝对 alpha**：`1.00` = 完全不透明（完全遮住壁纸），`0` = 完全透明。底色仍然来自当前情绪的官方令牌（侧栏 = `--dsw-specific-sidebar-fill`，主区/右栏 = `--dsw-alias-bg-base`），所以它始终跟着情绪走。刚装好时它显示的是调色板自己的 alpha（❨），一旦你拖动就变成你指定的绝对值，并且**优先于壁纸可见度的削薄** —— 否则"拖到底还是能看到壁纸"就无解 |
| **模糊** | 该面板自己的 `backdrop-filter: blur()`，0 = 完全清晰 |
| **高光** | 面板的镜边与投影强度：一圈渐变描边（左上最亮）+ 冷灰细边 + 面板外的接触投影。**投影是关键** —— 白色高光画在白色面板上本来就看不见，投影才会在浅色模式里真的显形 |

全局几何与光效：

| 控件 | 默认 | 说明 |
|---|---|---|
| **面板间隙** | 8px | 面板之间的留缝。**> 0** 时三个面板成为独立圆角卡片，外框透明、壁纸从缝里透出来；**= 0** 时面板贴合成**一整张玻璃**，由外框圆角统一裁切 |
| **外框圆角** | 0px | 整张外框的圆角。0 = 交给窗口自己的圆角 |
| **面板圆角** | 20px | 官方 `--dsw-radius-xl`（独立内容卡的标准半径） |
| **分隔线** | 0.35 | 间隙为 0 时的 0.5px 竖线强度。**有间隙时它按设计不出现**（留缝本身就是分隔），所以只在间隙 = 0 时拖动它才有意义 |
| **边缘折射** | 开 | 液态玻璃的镜边：在输入卡与消息气泡上叠一层 `feTurbulence + feDisplacementMap` 折射。开启时磨砂模糊会**降低 14%**，所以它的观感是"边缘更利、有透镜感"，而不是"更糊"。**不作用于内容弹窗**（如文件差异预览），参见下方"内容弹窗" |

**同心圆角的配方**：想让面板与外框同心，把「面板圆角」设为「外框圆角 − 面板间隙」。这也是官方圆角标准认的做法：`docs/ui-radius.md` 明确写着"由真实内缩推导的几何允许用 `calc()`"，标准档位里 `--dsw-radius-panel`(28) − 间隙 8 = `--dsw-radius-xl`(20)。

### 第一版为什么"调了看不出变化"

这是真实反馈逼出来的五个实现缺陷，都已修掉，记在这里免得以后重犯：

1. **透明度看不见**：面板底色是"白色 × 低 alpha"，而空闲态的渐变底本身接近纯白 —— 白上加白，alpha 从 0.52 降到 0.26 肉眼几乎无差。现在薄雾随透明度上升（玻璃的观感来自散射，"更透"应该表现为"更雾"），任何底色下都能看出变化。
2. **左侧栏的透明度/模糊尤其没效果 —— 真正的表面在更深处**：列里的**布局包裹层自己也画了一层底色**（ui-sidebar 的根就是如此），它盖住了列上的填充和列上的磨砂。只把直接子元素置为透明还不够，因为那一层可能是孙辈。现在插件会**下潜探测**（见下），把材质交给真正在画底色的那个元素。
3. **分隔线看不见**：alpha 基数写成 0.16 × 强度 0.35 ≈ **5.6%**，等于看不见；更糟的是它画在**列自身的 inset 阴影**里，而那正是被内层表面盖住的位置。现在基数 0.5（浅色）/ 0.42（深色），并且画在 `::after` 覆盖层上 —— 覆盖层是定位子元素，**绘制在内层内容之上**。
4. **右侧间隙错位**：官方 `.sidebarCol` 与 `.centerCol` 带 `overflow: hidden`，**`.rightbarCol` 没有** —— 右栏内容于是溢出到被 margin 缩小的盒子之外，把留缝"桥接"回主面板，看起来始终相连、且与渐变的缝错位。现在三个面板统一裁切（`data-rightbar-fullscreen` 的全屏浮层除外）。
5. **光感流动（我自创的动效）已整体移除** —— 见下方「关于沉浸光感」。它原本动画的是镜边伪元素的渐变位移，而那个伪元素被 `mask` 裁到**只有 1px 宽**：1px 里的渐变滑动，等于没有。我一度改成真实光带图层，但既然它既不是需求也不是任何设计语言的规定，就不该留着。
6. **我自己把内容表面做成了半透明**：官方主题里承载内容的令牌（卡片层级、弹窗、文档预览、代码块）**全是完全不透明的**，是我的调色板把它们换成了 0.52–0.54，视频才会从差异预览、设置页里透出来。这跟磨砂目标无关 —— 修法是把内容令牌在启用壁纸时抬到可读下限（见“谁透明、谁不透明”），并给页面级表面恢复磨砂。7. **模糊没效果的真正原因：`isolation: isolate` 会形成“背景根”**。`backdrop-filter` 只能滤镜“**背景根之后**”的内容，而 `isolation: isolate` 正好会创建一个背景根 —— 于是我把霜层挂在一个隔离元素上，它能看到的只剩面板自己的底色，没东西可滤。**填充为什么正常**：它只是普通背景色，不是背景效果。现在改用 `position: relative; z-index: 0`（同样产生层叠上下文、负 z-index 伪元素仍然画在底色之上，但**不**形成背景根）。同一修正也让输入卡、气泡与设置面板的模糊真正生效。

### 表面探测（为什么有限度地下潜）

侧栏、主区、右栏的可见表面不一定是列本身。插件在挂载、改动面板设置、或列被重建时做一次**有界的**探测：在列内找**最深的一层**「两个方向都覆盖 ≥85% 列尺寸、且自身在绘制（背景色有 alpha 或背景图不是 none）」的元素，把底色与磨砂交给它，并让列让位（`data-glass-delegate`）。

取**最深**而不是最先，是因为真正的表面往往在布局包裹层里面：把材质交给外层，磨砂仍然会被内层盖住。探测上限 48 个节点 / 5 层，且**不在 2.5 秒的廉价重标记轮询里跑**（那一步只重贴属性）。

注意这是"最深的一层够大的绘制元素"，不是"猜类名"：类名只用于**找到三根列**，之后一切都建立在本插件自己的属性上。`panelStatus().surfaces` 告诉你每根列是否委托给了内层表面，`panelStatus().surfaceDetail` 还会给出那个元素的标签与类名 —— 如果某根列的透明度/模糊仍然没反应，把这一项发我即可，不用猜。

## 接缝是怎么修掉的

你看到的"缝"来自官方布局本身：Windows 下 `.centerCol` 单独有一个 `border-radius: 16px 0 0 0`，而左侧栏是平直满高的，两者又各自画不同的半透明令牌 —— 那个 16px 圆角就在侧栏旁边露出一块外框底色，看起来像裂缝。官方圆角标准恰好点名了这类错误：*"避免单独圆角的填充在背景与描边之间留下一道月牙"*。

本插件的处理原则是「**一个轮廓只属于一个表面**」：

- **有间隙（默认 8px）**：三个面板各自是独立圆角卡片，四周等距内缩，外框透明 —— 圆角不再与任何平直边缘相接，缝本身变成了设计语言（面板浮在壁纸之上）。
- **无间隙**：面板全部方正，圆角只在外框上，`overflow: hidden` 把三栏裁成**一整张连续玻璃**，根本不存在两条边相接的问题。
- 官方那根 `border-right: 0.5px` 只在无间隙模式下保留（强度可调），有间隙时由留缝本身分隔。

外框的内缩用的是**网格项的 margin**，不是外框自身的 padding —— 因为外壳的列宽是 JS 按视口宽度算出来的，给外框加 padding 会让最后一列被裁掉 8px。margin 只影响面板自身，不影响轨道。

## 液态玻璃 + 光感

- **镜边高光（liquid glass）**：`::after` 上用 `mask-composite: exclude` 做出一圈**渐变描边** —— 左上强、右下留一圈冷灰反光（浅色模式下纯白高光在白面板上不可见，所以浅色态以冷灰细边 + 面板外投影承担轮廓），同时 `inset 0 1px 0` 给顶边一道镜面线，`inset 0 -28px 56px -34px` 给底部一层环境遮蔽。合起来才有"玻璃有厚度"的感觉，而不是一块磨砂色块。投影挂在面板本体上而不是覆盖层上 —— 覆盖层被 mask 裁到 1px 描边环，它的外投影会被一起裁掉。
- **霜层的正确写法**：`backdrop-filter` 不能放在一个 `isolation: isolate`（或 `filter`、`opacity < 1`、`mask`、`contain: paint`）的父元素里 —— 那些属性会创建**背景根**，滤镜只能看到根内部。正确做法是给宿主 `position: relative; z-index: 0`（得到同样的层叠上下文，不形成背景根），然后把滤镜放在 `::before` 上 —— 这样既能滤到壁纸，又不会让面板成为内部 fixed 元素的定位基准。
- **边缘折射**：一个内联 SVG 滤镜（`feTurbulence` → `feDisplacementMap scale=3.2`，**不做预模糊**）通过 `backdrop-filter: url(#…)` 作用在**小圆角表面**（输入卡 / 气泡 / 设置弹窗）上。位移量在背景 alpha 变化处最强、中心最弱，所以折射自然集中在边缘。开启时磨砂模糊降到 86%，让镜边保持锐利 —— 这正是"折射"和"更糊"的区别。**刻意不作用在整列上**：整列折射等于每帧把整个视口重新采样一遍，代价过高，成熟的玻璃主题也只做细部折射。
- **光感是静态的**：镜边高光 + 面板外的接触投影 + 面板内的底部环境遮蔽 + 随情绪变色的光（工作时偏冷、空闲时偏暖），再加上工作态那圈极慢的呼吸光晕。**没有任何自创的扫光动效**。

### 关于"沉浸光感"

你在第 6 轮提到"结合苹果液态玻璃和鸿蒙沉浸光感的特点"。我当时的做法是加了一条缓慢掠过的光带 —— 这是**我自己编的**，不是苹果或鸿蒙规范里的东西，你的评价（"跟鸿蒙的设计语言不是一个东西"）是对的。这次我试图核实它的官方定义，但 web search 缺 API key，Bing 上「沉浸光感」也没有对应的设计语言条目（只有"沉浸式翻译"之类的噪声），**所以我无法声称自己实现了它**，按这个前提，那条动效已经整体删除（连开关一起）。如果你手上有具体的参考（截图/录屏/文档链接），我照着做出准确的效果；否则就保持现在这套静态光感。
- **超椭圆圆角**：直接用官方 `corner-shape` 样式表 —— 官方已经在支持 `corner-shape: superellipse()` 的引擎上给所有元素套了超椭圆圆角，所以本插件**不去改** `corner-shape`，只用 `border-radius`（这也是官方"full-round 形状要配对 `corner-shape: round`"规则的前置条件）。


## 动态壁纸（每个状态一段）

**设置 → 通用 → 玻璃主题 · 动态壁纸**。两个状态各一行，各自独立：

| 控件 | 作用 |
|---|---|
| **链接 / 选择文件** | 该状态的视频来源。链接回车（或点出输入框）应用；文件立即播放并存入浏览器 IndexedDB |
| **清除** | 只清这一个状态（清掉后另一个状态的视频会自动接管两个状态） |
| **适配** | 裁切铺满 / 完整显示 / 拉伸铺满（两段共用） |
| **壁纸可见度** | **唯一的"看得清"旋钮**，见下 |
| **模糊** | 视频模糊 0–32px |
| **情绪染色** | 情绪色洗涤在视频上的强度（0–0.9） |

每个滑杆右侧都印着当前数值（不透明度 `0.52`、模糊 `18px`、间隙 `8px`…），方便按数值精确复现，而不是"拖到看着差不多"。

### 谁透明、谁不透明

我上一版把"读"的表面也做成了半透明 —— 这才是弹窗和设置页看不清的真正原因。官方主题里**承载内容的表面全是完全不透明的静态色**（`--dsw-static-neutral-bluish-00` 之类），是我的调色板把它们换成了 0.52–0.54 的 alpha，视频才会从差异预览和设置页里透出来。

现在按"看 / 读"分开，规则是可验证的：

| 类别 | 令牌 | 行为 |
|---|---|---|
| **看的表面**（壁纸的舞台） | `--dsw-alias-bg-base`（画布）、`--dsw-specific-sidebar-fill`（侧栏）、hover/active 态 | 按「壁纸可见度」削薄，画布最低到 0.06 |
| **读的表面**（内容） | `bg-document-preview`（文档/差异预览容器）、`bg-overlay`（弹窗）、`bg-layer-1/2/3`（卡片层级）、`settings-card-fill`（设置卡）、`markdown-code-block` / `inline-code`（代码）、`input-major` / `bubble` / `bubble-highlight` | **一旦启用壁纸，就抬到可读下限**（0.68–0.94），永远不因可见度变薄 |
| **文字与描边** | 全部标签色、边框色 | 一个字节都不改 |

这里有一个反直觉但重要的细节：**「保护」不是「削薄的反面」，而是独立的一步**。削薄只能减 alpha；保护只能加 alpha，而且只作用于上面那张表里的内容令牌 —— 测试对这一点有硬约束（未声明的令牌一旦获得 alpha 就判失败）。

### 灰字为什么看不清，以及修法

官方主题把"说明文字"和"弱化文字"画成中灰：`--dsw-alias-label-caption` 用 `neutral-bluish-400`、`--dsw-alias-label-dimmed` 用 `neutral-bluish-200`。在深色实底上没问题，但在**浅色或半透明的面板**上就糊成一片；而本插件原本只覆盖了 3 个 label 令牌，其余 12 个全走官方值 —— 这就是你看到的灰字。

现在共覆盖 **6 个** label 令牌，每一档都有硬性对比度门槛（对抬升后的卡片层测算，取最差组合）：

| 令牌 | 空闲/浅色 | 工作/浅色 | 门槛 |
|---|---|---|---|
| `label-primary` | 17.32 | 15.73 | ≥ 4.5 |
| `label-secondary` | 7.20 | 7.02 | ≥ 4.5 |
| `label-tertiary` | 5.14 | 4.91 | ≥ 4.5 |
| `label-caption` | 6.53 | 6.24 | ≥ 4.5 |
| `label-dimmed` | 3.86 | 3.75 | ≥ 3.5（本来就是"弱化"档，但仍须可读） |
| `label-document-preview` | 10.28 | 9.37 | ≥ 4.5 |

**诚实的边界**：如果你把某个面板的不透明度拖到很薄，灰字就是压在视频上，任何调色板都无法保证对比度 —— 面板不透明度本来就是这个权衡的旋钮。上表保证的是"面板保持默认厚度时"的可读性。

### 面板材质为什么曾经忽明忽暗

设置页每次重绘都可能让**表面探测**找到不同的元素：找到深处那层时，材质落在它身上（你设定的透明度生效）；找不到时，列自己上色，而深处那层会用它**受保护的近乎不透明的底色**盖住 —— 两种观感来回切，看起来就是"主面板透明度在两个值之间循环"。

两条修正：

1. **材质是粘的**：一旦把材质交给某个元素，只要它还在文档里就不再改判（元素消失才重新探测）。这直接消除了来回切换。
2. **弹窗永远不是面板表面**：探测会跳过 `role=dialog` / `aria-modal` 内部的元素。设置页开合时它就在列里，此前会被误判为表面。

### 磨砂只给"页面级"表面

设置界面那种大面板适合毛玻璃，而小的临时弹窗不适合 —— 差异预览的**背景被模糊**正是它原本看不清的原因之一。区分方式不猜类名，而是**量尺寸**：`role=dialog` / `aria-modal` 里，两个方向都超过视口 42% 的算"页面级"，由 JS 打上 `data-glass-frost="on"`，只有它才吃磨砂与折射 —— 所以设置界面又回到了你喜欢的毛玻璃状态。小弹窗保持自己的实底，清晰优先。缩小时标记会自动撤掉。

### 为什么刷新没用、重启才好：双重挂载

实时重载会在**同一个页面上再次执行 `apply()`**，如果上一个实例还没被卸下，就会留下
**第二张样式表与第二个壁纸舞台**。舞台原本在回退到 `<body>` 时是 `z-index: 0`，于是叠在应用之上 ——
屏幕上只剩下动态壁纸和一层朦胧遮罩，文字与边框全被盖住。刷新时重载器会再推一次新构建 → 再次双重挂载，所以**刷新不能救、只有重启能救**。

三道修正：

1. `start()` 先调 `sweepOrphans()`：清掉遗留的舞台、样式表、折射 SVG、所有钩子变量与 body 属性，**绝不在旧实例上重建**。
2. `apply()` 自带幂等：再次进来时先调上一个实例的 teardown（`window.__dshGlassMoodTeardown`）。
3. 舞台 `z-index` **永远为 -1**（不再看宿主）：即使真的漏了一份，也**不可能盖住应用**。

诊断：`__dshGlassMood.sweep()` 可单独清理遗留物（不卸载主题）；控制台里
`document.querySelectorAll('[id="dsh-glass-mood-bg"]').length` 应该**永远是 1**。

### 模糊为什么会在某些面板上惄惄失效：谁能看见壁纸，材质就放谁身上

`backdrop-filter` 只能看到**同一个背景根内部**画的内容。而侧边栏那类元素经常带 `contain: paint`
（为滚动性能）—— **它自己就是一个背景根**，拖在它身上的模糊层能看到的只剩它自己的底色，
于是**没东西可糊**。最阴的地方是：这种失效下 `getComputedStyle` 报的仍然是合法的 `blur(20px)`。

现在探测会把这件事算进去：**谁能看见壁纸，材质就放谁身上**。

- 候选表面能正常看到背景 → 照旧委托给它（避开内层覆盖）；
- 候选表面的祖先链上有背景根（`contain: paint` / `filter` / `opacity` / `isolation` / `mask` / `clip-path` / `mix-blend-mode`）
  → **材质留在列上**，并把**所有画底色的内层逐一挖空**（`data-glass-hollow`，背景色与背景图都清掉），
  让列自己的填充与模糊成为可见的那一层；布局恢复后又会自动改回委托。

且不再只靠控制台诊断：**面板行会直接印出结论**，例如

```
模糊挂载：左侧栏：材质在列自身，面板 alpha 0.52，内层是背景根（div.Sidebar_root: contain=paint）→ 已改挂到列上并挖空内层；主面板：材质在列自身，面板 alpha 0.64，背景可见；…
```

### 安排方式：列用伪元素（稳定版的做法），委托表面用元素自身

回头查了 v1.12.0（你让我备份的稳定版）：它用的是**同一个伪元素写法**，
所以它的左侧栏模糊当时就已经是坏的（你当时的反馈就是“左侧边栏模糊没用，其他两栏明显”）。
但那句话里藏着真正有用的信息：**列自己画底色时，伪元素是工作的**。

所以现在的规则是按“材质在哪”来分，而不是按猜测：

| 材质位置 | 模糊挂在 | 依据 |
|---|---|---|
| **列自身** | 伪元素 | 稳定版就是这么做的，且当时可见 |
| **委托的内层表面** | 元素自身 | 伪元素在那里报告合法值却采不到背景（实测） |

之前那个“含 fixed 子元素就回到伪元素”的自动切换已经**取消**：它把两个侧栏推回了那个不工作的安排，
而它防的那个问题（收起后打不开侧栏）已经由 `columnUsable()` 在另一层解决。
现在它只负责**报告**：那行诊断会写明“含 fixed 子元素”，一旦真有悬浮控件错位，能直接定位到哪个面板。

### 自检也修了两个毛病

1. 棋盘格原本是 **22px** 的大格，7px 的模糊洗不掉它，看起来仍然“清晰” → 现在是 **6px** 的细格，任何可见模糊都会把它化成平滑的灰。
2. 自检现在会**强制把三个面板的模糊提到 40px**（`data-glass-selftest`）——
   否则结论取决于你当时把滑杆拖到了哪里。问的是“机制在这个面板上有没有用”，不是“你设了多少”。

### 模糊为什么真的没生效：负层伪元素拿不到背景

真正的原因是我自己的做法，而不是应用的布局。用棋盘格实测得到的事实是：

```
左侧栏：模糊 21px（::before blur(18.06px) saturate(1.18)）   而棋盘格仍然清晰
```

也就是说：**属性确实生效了**（`::before` 确实拿到了 `blur()`），但**负 z-index 的伪元素并没拿到应用背后的壁纸作为背景**，
于是它模糊的是一片空白 —— 从外面看就是“滑杆拖了没反应”。之前几轮我一直在查应用侧
（是不是背景根、是不是内层覆盖），方向错了：问题在我把模糊放在伪元素上。

现在改成**模糊跟着材质走在同一个元素上**（`data-glass-blur-host=element`）—— 这是所有玻璃界面用的写法，
也是浏览器实测肯定生效的写法：背景就是它自己背后的那一层，不可能拿错。

**代价是真实的，所以我把它变成了检查而不是假设**：带 `backdrop-filter` 的元素会成为它 `position: fixed` 子元素的**包含块**，
这正是当初把侧边栏“展开”按钮弄丢的原因。所以探测会在每个面板内扫一遍（上限 400 个元素）：

- 没有 fixed 子元素 → **模糊贴在元素自身**（生效）；
- 有 → **回到伪元素**（保守，不会移动任何悬浮控件），并在那行诊断里写明原因；
- 无法询问浏览器（没有 `getComputedStyle`）→ 也选保守。

顺带说明一个可能会让你疑惑的数字：你设 21px 而算出 18.06px，是因为「边缘折射」开着时
`--gm-blur-scale` 会是 0.86（把一点模糊让给镜边的折射感），关掉它就是完整值。

### 为什么会把侧边栏的“展开”按钮弄丢

收起后的列不再是面板，但它仍然匹配 `[class*=\"_sidebarCol\"]`。而我为了阻止右栏内容“桥接”留缝，给每个面板加了 `overflow: hidden` 与 `margin` ——
**收起时应用会把重新展开的控件渲染在列自身盒子之外，于是被我裁掉了**。另一个候选原因是：`backdrop-filter` 会让元素成为其
`position: fixed` 后代的定位基准，而悬浮的展开按钮正是 `fixed`。两条都已修正：

1. **收起/未布局的列完全不碰**（宽度 < `COLLAPSED_MAX_WIDTH` = 56px）：不打标记、不剪裁、不加边距、不上材质，完全交回应用自己的样式；重新展开后下一次轮询就会恢复。
2. **面板模糊回到 `::before` 伪元素**（伪元素没有后代，不可能截走任何 fixed 元素）。之前伪元素看似无效是因为背景根问题，而那个问题已经用“舞台迁入外壳”解决了。
3. **外框只在间隙 = 0 时才 `overflow: hidden`**，让应用自己的悬浮控件不再被外框剪掉。

并且新增了应急开关：一个可能藏掉界面部分元素的主题，必须能在**不知道原因**的情况下被摆脱 —— 控制台里 `__dshGlassMood.off()` 会卸掉样式表、所有钩子与舞台。

## 按官方规范落地：玻璃只在导航层、背景感知、内容取色

这两套设计语言有一手文档，下表把每一条落到了具体实现上：

| 规范要求 | 出处 | 本主题的实现 |
|---|---|---|
| 玻璃给导航/功能层，**不要用在内容层** | Apple HIG、WWDC25 | 面板（侧栏/主区/右栏）才是玻璃；卡片、弹窗、代码块、文档预览一律实底（`WALL_PROTECT`） |
| 避免玻璃叠玻璃 | Apple HIG | 只有“页面级”大面板才加磨砂，小弹窗不参与 |
| 媒体上方的玻璃需要暗化层，**最高 35%** | Apple HIG Materials | 新增帧采样器：平均亮度 > `DIM_KNEE`(0.55) 时自动叠 `rgba(0,0,0,--gm-media-dim)`，**上限 `DIM_MAX` = 0.35** |
| 色调来自内容（“模仿真实有色玻璃”、“彩色内容的光溢到表面上”） | Apple HIG | 采样帧的主色相，按 `SPILL_MIX`(0.16) 洗到**镜边**（面板底色不动，对比度不受影响） |
| 对比度 ≥ 4.5:1 | Apple HIG | 六档 label 对比度门槛 + 内容保护下限 |
| 高透材质 + **依据背景自动保证可读** | 鸿蒙 `colorInvert` | 本主题用“背景亮度感知的暗化层 + 不透明内容表面”实现同一目的；浏览器无法逐字反色 |
| 赋色层必须带透明度 | 鸿蒙 `materialColor` | 所有洗色/镜边都是 rgba，没有不透明色块 |
| 自带阴影（优先于通用阴影） | 鸿蒙 `applyShadow` | 面板自有接触投影，不依赖应用的 shadow |
| 交互时发光 / 触点流光跟随 | 鸿蒙 `lightEffect`、Apple | **试过后移除**（v1.16 实现，v1.17 按反馈删掉）：它确实是规范里的行为，但实际看起来没有意义 |
| 按压弹性形变 | 鸿蒙 `interactive` | **已实现且保留**：按下时控件缩到 0.972，松手自动恢复 |
| Reduced Motion / Transparency / Contrast | Apple HIG | **三项都已响应**：运动降级、降低透明度、增强对比度（见下） |

参考：[Apple — Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/liquid-glass)、[Apple HIG — Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[WWDC25 — Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)、[鸿蒙 — 沉浸光感开发指导](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-immersive-light-sense-development)。

### 帧采样器：一个 24×14 的帧决定两件事

- **亮度 → 暗化层**：峰值亮度超过 0.55 时按比例加一层黑色遮罩，上限 0.35（苹果给的数字）。它在背景偏亮时保住对比度，偏暗时完全不出现。
- **色相 → 镜边**：采样帧的主色相按 16% 洗到镜边的两个彩色停点上，**面板底色不动**，所以可读性不受影响。
- **中性路径**：混合是从“原色”到“目标色相 × 自身明度饱和度”的 **RGB 直线插值**，途中经过中性灰。在色相环上走“最短弧”是错的：从冷色镜边（220°）到暖色内容（29°）的短弧**穿过品红** —— 那正是之前“发紫”的成因。
- **不猜**：无剪辑、帧还没好、帧偏暗（< 0.08）、帧近似灰色（饱和度 < 0.08）、或 **跨域视频污染了 canvas** 时，采样器宁可报“未读到”也不猜一个颜色。
- **节流**：每 4 秒采一帧（`SAMPLE_INTERVAL_MS`），远低于 1.5 秒的状态轮询；抽帧是一个 24×14 的离屏 canvas，跟整屏采样不是一个量级。
- 诊断：`__dshGlassMood.media()` 返回 `{ ready, brightness, hue, saturation, dim }`。

### 无障碍：降低透明度与增强对比度

苹果 HIG 把 Reduced Transparency / Increased Contrast / Reduced Motion 并列为玻璃材质必须响应的三项，
前两项现在由媒体查询读取（`prefers-reduced-transparency` / `prefers-contrast`），并且**系统切换时立即重绘**，不需要刷新。

**降低透明度**：所有“读”的表面变成**完全不透明**（气泡 / 输入框 / 弹窗 / 卡片层级 / 代码块 / 文档预览 / 设置卡），
面板也一律不透明，并且**可见度滑杆不再能把它削薄** —— “不要透明”正是要求取消“你得透着它看”的表面。
面板既然是实底，模糊层也就没了意义，所以 `backdrop-filter` 也一并跳过（少一份 GPU 开销）。

一个刻意的例外：**画布（壁纸）不动**。壁纸是你自己选的，而且它只在“没有任何东西需要被阅读”的面板之间露出。
如果你希望它彻底消失，直接把壁纸清掉即可。

**增强对比度**：六档文字全部取用**主文色**（层级改由字号与字重承担，而不是把字淡向背景），字段层级与弹窗也一并变为不透明。实测：

| 令牌 | 平时 | 增强对比度 |
|---|---|---|
| `label-secondary` | `#50556A` | `#17181C` |
| `label-tertiary` | `#666C7A` | `#17181C` |
| `label-caption` | `#565C6B` | `#17181C` |
| `label-dimmed` | `#7A808F` | `#17181C` |
| `label-document-preview` | `#3A3F4C` | `#17181C` |

诊断：`__dshGlassMood.preferences()` 返回两项当前状态；`__dshGlassMood.refreshPreferences()` 可手动重读。
没有 `matchMedia` 的环境不会报错，只是如实地报“无偏好”。

### 交互反馈：只保留按压形变

鸿蒙材质有两条交互反馈：`lightEffect`（触点流光跟随）和 `interactive`（按压形变）。我两条都实现了，
但**光斑跟随被你判为“没什么意义”，所以它已经整体删除**（v1.17）—— 不是默认关闭，而是不再占用三个
元素和每次指针移动的监听。一个没人要的功能不该留在代码里。

**按压形变保留**，并且有两个刻意的选择：

- **用 `scale` 而不是 `transform`**：这样**不会覆盖应用自己的 `transform` 动画**。（我上一次把 `backdrop-filter` 直接放在面板上时踩过同一类坑：抢了别人的属性）。
- **只作用于真正可点的控件**（`button` / `[role=button|tab|menuitem]`），不碰面板与布局。
- **开关**：面板行的「**按压形变**」，勾掉立即生效。
- **`prefers-reduced-motion`**：完全取消形变 —— 苹果 HIG 明文要求响应这个设置。

以后如果想把光斑要回来，它完整存在 tag `v1.16.0` 里（`git show v1.16.0:client.js`）。

### 为什么取色得放在面板上，而不是镜边上

第一版我把采样到的色相只洗到**镜边**，结果你看不出变化。原因是硬件层面的：镜边是一圈被 `mask`
裁到 **1px** 的渐变环，在 1px 的半透明细线上做 16% 的色相偏移，物理上就不可能看得出；而面板底色接近中性
（饱和度约 1%），单纯“旋转色相”同样不会移动任何像素。

现在两件事一起做：

1. **面板本身上色**：目标是“采样色相 × `SPILL_SATURATION`(0.34) × 自身明度（浅色面板降到 `SPILL_MAX_LIGHTNESS` 0.86 以留出彩度空间）”，再按 `SPILL_MIX`(0.45) 混合。
   实测：空闲/浅色面板 `rgba(255,255,255)` → 暖内容时 `rgba(244,239,233)`、冷内容时 `rgba(233,238,244)` —— **整块面板都在变，看得出来**。
2. **镜边仍然跟着变**（一致性），但它只是附带效果。

**可读性不能被它破坏**，所以有一条硬约束：在**最强取色**（完全饱和的色相 + 最大混合）下，四套调色板的正文对比度
实测 **14.4–16.2**（门槛 7），且任何一套调色板跌破该门槛时测试直接失败。

### 底部对齐：为什么中间面板没有底部间距

三个面板都带着 `margin-bottom`，但**声明了 `height: 100%` 的列会把它解析为网格区域高度**，于是外边距叠加在上面，
又把它推回窗口底部 —— 中间列正是如此，所以只有它贴底。现在把**底部内缩从面板的外边距改为外框的
`padding-bottom`**：内边距直接缩小网格区域，不论列声明了什么高度，它们都在同一条线上结束。

不必担心影响列宽：外框的**纵向**内边距不会碰到外壳用 JS 算出来的轨道宽度（那是横向的）。

### 工作模式为什么会把视频染紫

工作态的渐变本身是干净的钢蓝（`#CFE1F5` / `#16324C`），**紫色是叠加出来的**：

- 蓝色薄幕叠在偏暖的画面上，合成结果就是品红/紫（红 + 蓝）；
- 工作态把 `--gm-sat` 拉到 **170%**，把这个偏色又放大了一遍；
- 工作态的 `pulse` 光晕是饱和度很高的 `rgba(88,166,255,.22)`，在视频上面层叠 0.9 不透明度。

现在：**有视频时，情绪洗色保留明度、交出大部分色相**（`filter: saturate(.4)`）—— 它只“给画面盖一层调子”，不再给画面上色；脉冲改成中性冷光且弱化（有视频时 0.35）；`--gm-sat` 回到 **118%/128%**。

情绪的辨识度不靠洗色，而靠**玻璃本身**：面板底色、镜边、文字与光温都跟着情绪走。如果你仍然想要更多色调，「情绪染色」滑杆可以往上拖（它只控制薄幕浓度，色相已经被控住）。

### 为什么只有一个"壁纸可见度"

之前是「不透明度」+「清晰度」两个滑杆，你的反馈是"感觉效果差不多"—— 这个反馈是对的：**它们在动同一根感知轴**（"壁纸有多显眼"）。拖动视频自身的不透明度会让视频透过玻璃更亮，削薄面板会让视频更透，两者在肉眼上无法区分，而面板级透明度反而显得没效果。

所以现在合并为一根滑杆，它同时驱动两端，永远不会互相矛盾：

| | 壁纸可见度 = 0 | 壁纸可见度 = 1 |
|---|---|---|
| 视频图层强度 | 0.35 | 1.0 |
| 面板削薄（清晰度） | 0（面板原样） | 1（画布降到 0.06、侧栏 0.20） |
| 情绪染色保留 | 100% | 30% |

底层两个字段（`opacity` / `clarity`）仍然保留在配置与调试 API 里，脚本化控制时仍可分别写入。

**可读性不会被这个滑杆删掉**：只有"大面积底板"（画布 / 平台底 / 侧栏 / 层级底 / 卡片底）授权被削薄，而**承载文字的表面有硬下限** —— 气泡 ≥ 0.58、输入框 ≥ 0.55、设置卡 ≥ 0.50、弹窗 ≥ 0.62、代码块 ≥ 0.55。颜色本身（文字色、边框色、品牌色）一个字节都不动，只改 alpha。

> 直说风险：视频内容是你选的，主题无法知道它多亮。在极端组合下（浅色模式 + 全黑视频 + 清晰度拉满），少数文字仍可能不够清楚 —— 这是"把视频放清楚"的固有代价，此时降低清晰度或给视频加个模糊即可。

### 状态切换的过渡

两个状态各自一个 `<video>` 元素，**两段都常驻并持续播放**（静音、循环）。切换情绪时只是 CSS `opacity` 交叉淡入，用主题自己的过渡时长（进工作 260ms、回空闲 900ms）—— 没有解码器重启、没有黑帧、没有卡顿。测试里专门断言了"切换后两段视频的 `src` 未变、未重新 `load()`"。

只配了一段视频时，那一段会标记为 `both` 同时服务两个状态（只有**一个**元素在解码，不会重复播放同一文件）；两段都配了才各占一个元素。

### 其它边界（都是浏览器规则）

- **强制静音**：浏览器只允许「静音 + inline」的视频自动播放。
- **格式**：`mp4` / `webm`（H.264 / VP9 最稳）。
- **大文件**：超过约 400MB 会提示（IndexedDB 写入可能明显变慢）；链接方式不占浏览器存储。
- **链接跨域**：普通 `<video>` 播放不需要 CORS，但服务器若校验 Referer/鉴权会失败，此时改用本地文件。
- 壁纸是**本机存储**（localStorage 配置 + IndexedDB 文件），不跨设备同步。
- **旧版自动迁移**：v1 的单视频配置（顶层 `source`/`url` + IndexedDB 的 `wallpaper` 键）在启动时自动搬进"空闲"槽，并把字节复制到新键后释放旧键，你不需要重新设置。

## 它怎么判断"空闲/工作"

唯一信号源是**有没有会话在干活**，按可靠性依次尝试：

1. `uiSession.sessionStatus` —— 每会话状态表（`running` / `pendingInteraction`），首选；
2. `sessions.list.getSnapshot().byId` 行上的 `running`，其次；
3. `sessions.binding(id).session.getSnapshot().running`，兜底；
4. 每 1500ms 一次快照轮询作为安全网（纯内存读取，无 I/O）。

**滞回（避免闪烁）**：

| 常量 | 值 | 作用 |
|---|---|---|
| `WORK_ENTER_MS` | 120 | 进入"工作"只需极短防抖，响应要快 |
| `IDLE_ENTER_MS` | 1600 | 工具步骤之间的空隙不回到珍珠白，避免来回跳 |
| `MIN_DWELL_MS` | 600 | 两次切换之间的最小间隔 |
| `COUNT_PENDING_AS_WORK` | true | 停在"等你确认"上的回合仍算工作（回合没结束） |
| `POLL_MS` | 1500 | 兜底轮询 |

首屏不做滞回：刷新页面时正有回合在跑，直接冷色落地。

## 玻璃是怎么做出来的（以及为什么这样做）

- **舞台**：一个 `position:fixed; z-index:0` 的图层放在应用框架**后面**，`#root` 抬到 `z-index:1`。舞台内部从下到上是：`<video>`(空闲) → `<video>`(工作) → 空闲渐变 → 工作渐变 → 工作呼吸光晕。
- **模糊只在三个已验证安全的目标上**：输入卡 `[data-composer-card]`、消息气泡 `[data-time-hover-root] [class*="_bubble"]`、设置弹窗 `[role="dialog"][aria-labelledby]`。`backdrop-filter` 会让元素成为**所有 fixed 后代的包含块**（菜单、tooltip、toast 会跑偏），所以它挂在 `::before` 伪元素上（父级 `isolation: isolate`），绝不用在 `#root` 或三栏容器上。
- **一次性过渡窗口**：切换情绪的瞬间给 `body` 加 `data-glass-fading`，只在那 1.1 秒内给 `[class*="_card"] / _panel / _sidebar / _bubble` 等表面开 `transition`，所以颜色切换平滑而 hover 反馈平时不受影响。
- **工作时的呼吸光晕**只有一个 5.5s 的 `opacity` 动画，且在 `prefers-reduced-motion: reduce` 下关闭。
- 全部写在一个**自包含 client bundle** 里（`window.__ModuleLoader__.load({...})`），零构建、零 npm 依赖；`dispose` 时令牌层、样式表、舞台、两个 object URL、slot 行、body 属性与变量、调试句柄全部收回。

## 验证

```powershell
node test/glass-mood.test.mjs
```

42 项检查。原有：挂载/卸载彻底性、首屏情绪、工作切换与空闲滞留、步骤间隙不闪、等待确认算工作、两条回退路径、钉住情绪；壁纸的空状态、链接与实时旋钮（含越界钳制）、清晰度预算、本地文件与按槽清除、两段视频切换不重载、单段回落双状态、跨重挂载恢复、按槽诚实降级、v1 迁移、无 IndexedDB 时不清空用户选择；令牌合规与全部对比度门槛。逐轮累加的锁：

- **表面探测**：嵌套的侧栏表面被发现并接管材质、列让位（`data-glass-delegate`）；自身绘制的列保持材质；**全透明的满幅包裹层不会被误判**；表面元素消失后探测如实报告并把材质交还列；
- **不透明度是绝对 alpha**：`1` 真的完全不透明、`0` 真的全透明、显式值优先于可见度削薄、`-1` 回到跟随调色板，且回显的是**实际生效的 alpha**；
- **内容保护**：启用壁纸后，文档预览容器 ≥0.94、弹窗 ≥0.90、卡片层级 ≥0.84、代码块 ≥0.86、气泡 ≥0.72、输入框 ≥0.80；同时**未声明的令牌不允许因为保护而获得 alpha**，而画布/侧栏仍然照常削薄；
- **收起态**：宽度 <56px 的列不得带任何本插件钩子（并且要如实上报"未识别"），重新展开后又能恢复；外框只在间隙 = 0 时才剪裁；`off()` 必须清掉样式表、钩子、舞台与 API；
- **色相中性**：有视频时情绪洗色必须带 `filter:saturate(.4)`、脉冲层必须是中性冷光、且 `--gm-sat` 必须 ≤120%（闲置）/ ≤130%（工作），不允许再出现鲜蓝色脉冲；
- **背景根**：生成的 CSS 里不允许出现 `isolation:isolate`；
- **舞台位置**：壁纸舞台必须挂在应用外壳内（同一个背景根）、带 `data-glass-in-shell`、外壳重建后会自动搬回去；**舞台永远处于负层级**，即使漏一份也不可能盖住应用；棋盘格自检可挂上又可摘下；诊断报告包含每个面板的实际 `backdrop-filter` 与舞台宿主；
- **双重挂载**：`start()` 必须先清理遗留物（舞台/样式表/折射/钩子），一次页面上的两次挂载只能剩**一个舞台与一张样式表**；
- **灰字对比度**：secondary/tertiary/caption/document-preview 均 ≥4.5，dimmed ≥3.5，四套调色板逐一校验；
- **材质稳定性**：重复探测不改变已委托的表面、弹窗内元素永远不会被选为面板表面（且此时如实上报无表面）、元素脱离后才交还；
- **磨砂分级**：视口 42% 以上的大面板被打上 `data-glass-frost`、小弹窗不被打上、缩小后撤回、卸载后清空；
- **帧采样**：亮帧得到遮罩（且 ≤0.35）、暗/灰/污染/无剪辑四种回退、采样节流、暗化层是舞台最后一层；
- **取色**：面板确实被染暖（暖内容时 R > B）、开关能还原原始填充、且**最强调色下正文对比度 ≥7**；
- **底部内缩**：面板不得带底部外边距，外框的 `padding-bottom` 必须存在（`height:100%` 的列才会与其余两列对齐）；
- **交互**：按压关键帧存在、受开关门控、**只用 `scale`**（不得用 `transform`，以免覆盖应用动画）、reduced-motion 取消它；并且**光斑已彻底删除**（CSS 与 DOM 里都不允许再出现）；
- **无障碍**：降低透明度 → 所有承载文字的表面完全不透明、画布不动、磨砂层被跳过；增强对比度 → 六档文字全部取主文色、弹窗变实；两项都能在系统切换时**不刷新即重绘**，且卸载时释放监听。
- **探测取最深**：嵌套的多层表面中选中真正在绘制的那一层，并把它报告给 `surfaceDetail`；
- **壁纸可见度是一根轴**：0 → 视频 0.35 / 不削薄，1 → 视频 1.0 / 面板降到 0.096，两端都由同一个 patch 驱动；
- **数值回显**：两行设置的每个滑杆都输出格式化数值（`1.00` / `0px` / `8px` / `20px` / `0.35`）；
- **回归锁**：接触投影随高光增强、分隔线 alpha 达到可见量级、浅色态镜边是冷灰而非纯白、折射滤镜不含预模糊且开启时降低磨砂模糊、没有扫光动效残留、这些变量在卸载时全部收回。

## 调参速查

- **颜色**：`PALETTES.idle` / `PALETTES.work` 的 `light` / `dark` 数组（顺序与 `TOKEN_KEYS` 一一对应）。改完跑测试。
- **削谁、削多少、下限多少**：`WALL_THIN` 表（`[token, rate, floor]`，只含看的表面）。面板底色也走这张表，所以调整它同时影响壁纸可见度与面板薄厚。
- **内容可读下限**：`WALL_PROTECT` 表（`[token, floor]`）。壁纸开启时这些表面**只升不降**；若某个新组件在壁纸下看不清，把它的令牌加进这张表。
- **页面级表面的判定阈值**：`BIG_SURFACE_RATIO`（默认 0.42）。
- **材质粘性**：见 `surfaceAttached()` 与 `discoverSurfaces()`。若你真的想强制重新探测，调 `window.__dshGlassMood.probe()` 前先把旧表面从 DOM 里移除（或刷新页面）。
- **面板默认值**：`PANEL_DEFAULTS`（三个面板的 `opacity`（`-1` = 跟随调色板）/`blur`/`sheen`，以及 `gap`/`frameRadius`/`panelRadius`/`divider`/`refraction`）。
- **表面探测的边界**：`SURFACE_MAX_NODES`(48) / `SURFACE_MAX_DEPTH`(5) / `SURFACE_MIN_COVERAGE`(0.85) / `SURFACE_MIN_ALPHA`(0.04)。若某根列没被委托（`panelStatus().surfaces` 为假）而你想让它委托，先放宽 `SURFACE_MIN_COVERAGE`。
- **可见度下视频的最低强度**：`VISIBILITY_MIN_CLIP`（默认 0.35）。
- **取色强度与可见度**：`SPILL_MIX`(0.45) / `SPILL_SATURATION`(0.34) / `SPILL_MAX_LIGHTNESS`(0.86)。嫌太淡就调大 `SPILL_SATURATION`；担心字不够清楚就调小 `SPILL_MIX`。
- **外壳选择器**：`PANEL_SELECTOR`（左 `_sidebarCol`、主 `_centerCol`、右 `data-rightbar-col`）。官方若改类名，改这一处即可，样式侧不用动。
- **镜边与折射**：`panelRim()`（高光渐变的三个色标 + 环境遮蔽 + 分隔线）、`REFRACTION_SVG`（`baseFrequency` / `scale` 决定折射的纹理与强度）。
- **染色在满清晰度下保留多少**：`TINT_THROUGH_CLARITY`（默认 0.3）。
- **壁纸默认值**：`VIDEO_DEFAULTS`（`fit` / `opacity` / `blur` / `tint` / `clarity`）与 `VIDEO_WARN_BYTES`。
- **渐变（无壁纸时的底）**：`IDLE_STAGE_LIGHT/DARK`、`WORK_STAGE_LIGHT/DARK`。
- **模糊与速度**：`--gm-blur` / `--gm-sat` / `--gm-fade` / `--gm-sheen-mood`（`body[data-glass-mood]` 与 `=work` 两条规则）。
- **节奏**：`IDLE_ENTER_MS` / `WORK_ENTER_MS` / `MIN_DWELL_MS` / `POLL_MS` / `COUNT_PENDING_AS_WORK`。
